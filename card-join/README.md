# Card Join — подключение игроков к матчу по ссылке

Отдельный Docker-сервис по экранам прототипа «Поликарты» (`Поликарты прототип.html`):
реализован **только сценарий подключения по ссылке-приглашению**, без игровой логики.

Что работает по-настоящему (в прототипе это были демо-кнопки):

| Экран прототипа | Здесь |
|---|---|
| 1. Подключение / 1a. Нет соединения | реальный пинг `/api/health` |
| 2. Имя игрока | упрощённый шаг: только имя (без пароля — авторизация вне этого этапа) |
| 3. Главное меню → «Создать матч» | матч реально создаётся на сервере |
| 4. Лобби (хост) | настоящая ссылка-приглашение `http://<хост>:8080/m/КОД`, копирование, ожидание |
| 5. Приглашение (гость) | гость открывает ссылку с другого устройства → «Хост зовёт вас в матч» → «Присоединиться» |
| 6. Соперник найден | оба игрока синхронно видят экран VS с именами друг друга |

Экраны 7–11 (тренер, раунды, результат) — **не входят** в этот этап.

## Запуск

```bash
docker compose up -d --build
```

Сборка мгновенная и без интернета: внутри нет `npm install` — библиотеки интерфейса
(Vue 3, PrimeVue) лежат прямо в `public/vendor/`, сервер — чистый Node.js без зависимостей.

- Сервис: `http://localhost:8080`
- Проверка: `curl http://localhost:8080/api/health` → `{"ok":true,...}`

## Как подключить двух игроков по ссылке

1. Игрок A открывает `http://localhost:8080`, вводит имя, нажимает **«Создать матч»** —
   получает ссылку вида `http://<адрес-машины>:8080/m/K7Q2MX`.
2. Отправляет ссылку игроку B (в мессенджер, QR и т.п.). Вместо `localhost`
   должен быть адрес машины, видимый второму игроку (IP в локальной сети, домен и т.д.).
3. Игрок B открывает ссылку, вводит имя → видит «Игрок A зовёт вас в матч» → **«Присоединиться»**.
4. Оба автоматически (опрос раз в 1.5 с) попадают на экран **«Соперник найден»**.

Обновление страницы не выбрасывает из матча: игрок и его роль восстанавливаются
по `playerId` из localStorage (хост вернётся в лобби, гость — в свой экран).

## Правила подключения (как в прототипе)

- В матче ровно **два места**. Третий игрок по той же ссылке увидит:
  «Ссылка больше не работает: матч отменён или в нём уже два игрока».
- Хост может **отменить матч** в лобби — у гостя ссылка перестаёт работать.
- Если один из игроков выходит с экрана «Соперник найден», второй видит «Соперник вышел из матча».
- Матчи хранятся в памяти контейнера: закрытые живут 1 час, любые — не дольше 12 часов
  (автоочистка). После перезапуска контейнера матчей нет.

## API (минимальный, только подключение)

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | пинг |
| `POST /api/matches` `{playerId, name}` | создать матч (хост) → `{code, ...}` |
| `GET /api/matches/{код}?playerId=...` | состояние матча: `WAITING / READY / CLOSED`, имена, ваша роль (polling) |
| `POST /api/matches/{код}/join` `{playerId, name}` | присоединиться по ссылке (гость) |
| `POST /api/matches/{код}/leave` `{playerId}` | выйти / отменить матч |

Матч-код — 6 символов без похожих знаков (без `0/O`, `1/I/L`), как на экране прототипа.

## Связь с остальными частями проекта

- `card-game-db/` — PostgreSQL с той же ER-схемой (этап 1);
- `card-game/` — полная версия с Kotlin-сервером и игровой логикой;
- `card-join/` (этот сервис) — промежуточный этап: реальное подключение по ссылке.
  Когда дойдёт до интеграции, matchmaking переедет в основную БД
  (таблицы `matches.invite_token` и `match_participants` уже есть в схеме).
